# How ParisaOCR is put together

A page goes through four steps; searchable PDFs and EPUB books are built on their output. Each module below is small and replaceable.

| Step | Module | What it does |
|---|---|---|
| Pages | `pages.py` | Collects inputs; a PDF's scanned pages are extracted with `pdfimages` (lossless; each page image is checked against a small `pdftoppm` render and turned if it is stored mirrored or rotated), born-digital pages rendered with `pdftoppm`. A page image that does not match the render (a scan set inside a larger page, in strips, a stencil over a background, text stamped over it) is drawn from the page's images as the content stream places them (pikepdf: `cm`/`Do` with the CTM, stencil masks in their fill grey, /Rotate), and rendered only when that does not match either. Text stamps — the same string drawn over the scan on 30%+ of the scan pages, a download site's name — are found by `pdf_text_stamps` and stripped from the pages before any rendering. |
| Lines | `detectors.py`, `detect.py` | Finds text lines. Default: PP-OCRv6 small (`PaddleDetector`, ONNX Runtime, bundled model). Also PP-OCR v6 medium/tiny and v5 (downloaded by RapidOCR), Kraken's baseline segmenter, Surya (optional extra). Pages narrower than 1,600 px are enlarged and wider than 2,000 px reduced for detection; detections are cached per page. |
| Crops | `pipeline.py` | Cuts each line with a margin of 0.4 x the page's median line height sideways and half of it vertically (detector boxes hug the letter bodies; the dots of Persian letters lie outside), paints neighbouring lines inside the margin in the background colour, enlarges small crops. Boxes much taller than a line are marked as blocks. |
| Reading | `kraken_reader.py`, `bidi.py` | Stacks the crops of a batch into one image and reads them with the Kraken model in GPU/CPU batches; blocks are split into lines at the rows with least ink first. PP-OCR inputs are padded to the training width (kraken#810). The model's visual-order output is turned into reading order by `bidi.to_logical` with each line's own base direction, keeping ZWNJ (kraken#809). Word boxes run from space to space. Short, unsure lines (4 characters or fewer below 80% confidence, unless only a number) are dropped as non-text marks. |
| Order and output | `order.py`, `output.py` | Groups lines into columns read right to left; writes text, hOCR (line and word boxes on the original page) and JSONL. |
| Searchable PDF | `pdfout.py` | Builds an invisible text layer (reportlab, rendering mode 3): per line one run in display order (`bidi.to_display`), stretched to the line's width, in the bundled Vazirmatn font. For a PDF input the layer is laid over the original pages as a form XObject (pikepdf), placed in media-box coordinates through the page's /Rotate; pages with an existing text layer (100+ letters by `pdftotext`) are skipped unless `--pdf-text add`, except that a layer in another script than our text (glyph codes from a broken OCR) is replaced; `--pdf-text replace` replaces the text of every scan page, and text stamps found by `pages.pdf_text_stamps` are removed from all pages. For image inputs a new PDF holds the image and the layer. `PARISAOCR_PDF_VISIBLE=1` draws the layer in red, to check its placement. |
| EPUB | `ebook/` | `parisaocr epub`: reads a book's pages as above, then works out the book from the JSONL by geometry and the printed contents, without a language model. `layout.py` per page: text, figure or blank; running header or page number at the foot (zones set from the book's usual first and last lines, so wide scan margins do not matter); footnotes below the separator rule or below a gap; ruled tables; figures. `order.py`: book order from the printed page numbers. `refine.py`, `markers.py`: stacked fractions, footnote markers found in the image, verse lines. `structure.py`: contents parsed and matched, chapter openings, headings, paragraphs (the book's own paragraph indent is measured), quotes, verse and poems, notes. `roles.py`: 46 layout features per line and the bundled line-role models (gradient-boosted trees exported from scikit-learn as `models/roles/*.npz`, evaluated with numpy) — a line's role, P(footnote), P(heading), P(starts a note), heading level — which `layout` and `structure` consult: a learned footnote area where no separator rule is found, learned chapter openings and title blocks, heading evidence. `epub.py`, `fonts.py`: the EPUB 3 package; `report.py`: the QA report. `review.py`, `marks.py`: `--review`, a local page (stdlib HTTP server on 127.0.0.1, one HTML file, no dependencies) where the reader marks parts, chapters, sections and figure pages; the marks file replaces the rules' openings in `structure.build` and records the rules' own decisions for comparison. `gemini.py`: `--llm`, the page labeller (stdlib REST client): each page image with its OCR lines tagged by number → line roles, heading levels, note numbers and markers, page type, printed page number, contents entries (`p-NNN.json`); then the book's outline from all headings (`book_outline.json`) and its bibliographic data from the cover, title and imprint pages (`book_meta.json`), kept in the work directory. With `--llm openrouter:VENDOR/MODEL` the same questions go to OpenRouter (`OpenRouter` in `gemini.py`, an OpenAI-style client behind the same interface, privacy routing fixed). `notenum.py`: footnote numbers the line reader lost, re-read from the image with the recognition model's decoding limited to digits (`notenum.json` in the OCR folder; `source.load` applies them and joins raised numbers boxed apart). `labels.py`: puts those labels on the lines and lets them decide — headers, page numbers and noise dropped, footnotes and endnotes by their numbers, openings from the outline, contents entries from the labels; the layout rules keep pages without labels. |
| App | `app/` | `parisaocr app`: a local web page for the whole process. `server.py`: stdlib HTTP server on 127.0.0.1; the address it prints carries a random key that becomes a SameSite=Strict cookie, every request must name the server as its Host (DNS rebinding) and every POST must carry the `X-ParisaOCR` header; serves the page (`static/`, no external scripts or fonts), the jobs' files, page thumbnails and the files inside an EPUB for the preview, and saves API keys to `~/.config/<service>/api_key` (mode 600). `jobs.py`: a job is a folder in the app's home (`job.json`, `input/`, `out/`, `logs/`); each run is the same `parisaocr` command in its own process (killed with its children on cancel), one at a time, its `@progress` lines (`progress.py`, printed with `PARISAOCR_PROGRESS=1`) moving the job's stages; a book with a language model runs first with `--llm-estimate` and waits for the cost to be agreed; the chapter review is `epub --review` with the labels already given instead of `--llm`. `forms.py`: the forms are read from the command line's parser (flags, defaults, choices, types) and only grouped and labelled here, so every option is on the page; the form's values become the command's arguments, checked by the parser before anything runs. |

`reader.py` is the Tesseract alternative to the Kraken reader (`--model TESSDATA:LANG`);
`cut.py` (`parisaocr cut`) cuts the lines of scanned book pages into crops plus a
manifest for building training data; `fa_text.py` holds the Persian text
normalization shared with training and evaluation.

System programs: Poppler's `pdfinfo`, `pdfimages`, `pdftoppm` and `pdftotext` for PDF input;
Tesseract only for `--model TESSDATA:LANG` and `parisaocr cut`.
